# Public demo link serves one fixed, fake seeded account — never a real user's data

The public read-only demo link (for the supervisor's showcase page) needs an unauthenticated route showing real-looking data. Two options existed: reuse `scripts/seed-test-data.js`'s existing dedicated demo account, served strictly read-only to every visitor; or let a real user opt in to make their own account publicly viewable. The second was rejected outright — it needs consent UX to build safely, and any bug in that path leaks a real person's actual review data. Decided: **the demo route always serves the same fixed, clearly-fake seeded account, and every mutating action (create/edit/delete/review/skip) is rejected server-side for that account** — read-only is enforced in the backend, not just by hiding buttons in the frontend, so there's no path to actually writing through this route regardless of what the client sends.
