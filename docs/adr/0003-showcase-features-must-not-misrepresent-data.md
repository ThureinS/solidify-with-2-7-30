# Showcase/feature-packed additions must not misrepresent data; pure decoration is exempt

The production push (see [developer-handover.md §10](../../developer-handover.md)) calls for the app to be "huge, feature-packed, with animations" for a public showcase page, while still holding up to a technical audience (the supervisor) evaluating real engineering. Those pulled in different directions until resolved into one filter: **any addition that represents or claims information (a number, a state, a progress signal) must be backed by real stored/computed data — never a plausible-looking mock.** Pure decoration with no informational claim (hover states, page transitions, loading spinners) is exempt; it isn't asserting anything that could be false.

This generalizes a rule the project already applied twice before ever writing it down: rank titles/milestone toasts were rejected as "a game skin bolted onto a study tool" (no real signal behind them), and the review-history moon grid went through a whole audit session (developer-handover.md §10c) fixing labels that claimed more than the underlying data supported. Writing it down now so the next feature added under the "impressive/showcase" banner doesn't reintroduce the same mistake from scratch.
